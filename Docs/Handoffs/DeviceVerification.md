## 4. Preconditions — both are physical

Gate 60 exits 2 (SKIP) rather than failing when the physical world is not ready,
and a skip is never a pass. Two things can block it, and the second only appears
after the first clears:

1. **The iPad must be unlocked, and left unlocked.** The current block is
   `developer disk image services unavailable`. Xcode mounts the DDI on first
   connection to an unlocked device. Everything else already passes: the device
   is paired, Developer Mode is on, it answers live queries, signing is valid.
2. **The development profile may need trusting on the device.** If launch fails
   with "explicitly trusted", gate 60 skips and prints the fix: on the iPad,
   Settings → General → VPN & Device Management → Developer App → trust the
   Apple Development certificate. Nothing on the Mac can do this for you.

Target device, as configured in `Tools/lib.sh`: **`Phillip’s iPad`** — an iPad
Air (5th generation), iPadOS 26.5.2. Note the curly apostrophe in the name; it
is matched literally. Override with `TN_DEVICE_NAME` only if the device was
renamed, never to point at a different iPad.

## 5. Commands

```sh
Tools/preflight-device.sh   # every device precondition, with specific reasons
Tools/gate.sh 60            # the device gate alone
Tools/gate.sh               # the full run; writes Artifacts/gate-report.md
```

Preflight exit codes: 0 ready, 2 BLOCKED (something physical must change), other
= misconfigured, which is a failure and not a skip. Gate 60 builds signed for
the resolved device id, installs, launches, and confirms the process is running.

Set `TN_TRACE=1` in the launch environment to mirror the app's `CanvasLog` events
to stderr, which `devicectl device process launch --console` captures without
privileges. The unified log needs root or Console.app to read back off a device,
so `TN_TRACE` is the only log sink usable from a script.

## 6. What to exercise by hand, and why

The unit suite covers these mechanically; none of it proves the behavior on real
hardware with a real Pencil. Exercise each and record what happened.

**Launch and first contact.** Fresh install: does one blank portrait page appear
and take ink immediately? A crash on the *first stroke* has specific history —
`PKCanvasView` built too early comes up with incomplete gesture state and takes
UIKit down inside `-[UIGestureRecognizer _delayTouchesForEvent:]`, and the page
boundary is a `CALayer` rather than a subview for the same reason. If you see a
first-touch crash, that is where to look; it is not a flake.

**Page extension — removed 2026-07-30, do not exercise.** Downward growth is
gone; the page is one fixed size. Any build still offering an extend control is
stale.

**Scroll and zoom.** Pinch to both extremes and pan to every edge. Confirm you
can reach the page's own bottom edge at each zoom level, and that ink stays
attached to the page. `UIScrollView` owns `contentSize` rescaling during zoom;
this is checking that the page projection agrees with it in practice.

**Background flush (changed today).** Background the app immediately after a
stroke and return: ink must survive. The flush is now a single best-effort pass
rather than a loop, so if execution time expires the editor stays dirty and
retries on foreground — losing an *acknowledged* save is a failure, but a
still-dirty document after a fast background/foreground cycle is correct.

**Autosave under continuous writing.** Write continuously for a few minutes and
watch the `TN_TRACE` save events: confirm serialization reports off-main, and
that saves are spaced rather than chained back to back. The adaptive debounce is
not expected to engage at realistic document sizes — it only widens the interval
above roughly 125 ms of serialize cost, which is far more ink than a normal
page. Seeing a flat 500 ms is the expected result, not a defect.

**Failure surfacing.** If any save fails, the on-screen error must appear and a
retry must happen on its own within about five seconds without you drawing again
or tapping Retry.

## 7. Two things in the console that will mislead you

- Gate 50 greps for `CONTRACT VIOLATION`. **Nothing in the app can emit that
  string anymore** — the assertion that produced it was deliberately removed when
  the one-live-canvas rule was loosened. Its absence proves nothing.
- That same grep also catches `Fatal error` and `Precondition failed`, and there
  is one live precondition: `installDrawing` refuses to run once the canvas is
  editable. If it fires it is a **real defect** — it means a loaded drawing was
  about to overwrite live ink — so capture the stack and report it rather than
  working around it.

## 8. What you must not do

- **Do not judge Pencil feel.** Initial contact, stroke fidelity, palm
  rejection, Pencil/touch separation, pan/zoom feel, and tool ergonomics are
  Phillip's verdict alone. Record observations; render no opinion as a verdict.
- **Do not report `INCOMPLETE` as success.** If a gate skips, say so, name it,
  and say what evidence is missing.
- **Do not change the `Docs/Plan/PLAN.md` status board.** A line may only be
  marked complete on a PASS, or on an INCOMPLETE whose skipped gates are named
  explicitly as outstanding evidence.
- Compilation is never behavioral proof, and neither is a simulator run.
