# TuberNotes agent contract

TuberNotes is a fully performant iPad notebook canvas targeting parity with
GoodNotes. Optimize, in order, for ink integrity, interaction
latency, document durability, spatial correctness, and feature breadth.

Read before changing application code: `Docs/Contract.md` — the rules in
force. `Docs/Queue.md` is Phillip's own map of open problems and their
state — read it to orient, not because it assigns your work; fix whatever
the codebase actually needs. `Docs/Unproven.md` says what this project has
not earned. `CONTRIBUTING.md` says how to work here — the loop, the
evidence, and the gotchas. Why a rule is the way it is lives next to the
rule; known defects live in the code as `KNOWN DEFECT:` blocks.

## Build

`project.yml` is the only project source. The `.xcodeproj` is generated by
XcodeGen and gitignored — an edit made to it directly is silently lost.
Change `project.yml`, then:

```bash
xcodegen generate
xcodebuild test -project TuberNotes.xcodeproj -scheme TuberNotes \
  -destination "platform=iOS Simulator,name=$(< Tools/pinned-simulator)"
```

The simulator name is pinned in `Tools/pinned-simulator`, its only home;
`CONTRIBUTING.md` says why. Anything that
differs per developer — signing team, bundle prefix — lives in gitignored
`Local.xcconfig`, never in `project.yml`.

## Rules

The authoritative statements live in `Docs/Contract.md`. Cite rules by name,
not number, and where this index and that file differ, that file wins:

- **Custody** — each piece of state has one owner, and the owner holds the
  value. The notebook holds the ink; the canvas is told, never asks; views
  draw state and send requests.
- **Structure** — nothing runs per Pencil sample except PencilKit; per-frame
  work lives in `TNCanvas`; file I/O lives in the two stores and the import
  reader; the module graph is a test.
- **One save** — leaves, then page files, then the index; only `compact()`
  deletes.
- **Invalid states fail loud** — `TNPrecondition`, never a clamp or a
  default.
- A change to a rule edits `Docs/Contract.md` and the commit subject starts
  with `CONTRACT:`.

One rule's home is this file: **smallest change that proves the queue item.**
No future notebook, PDF, AI, collaboration, or sync abstractions early.

## Definition of done

Done means Phillip has pushed the commit to `main` and CI is green on it —
never that it compiled. There are no pull requests. Green CI means it built
and the tests passed; **it is silent about ink**, because the simulator has
no Apple Pencil. This is the one home of the device rule: a change to the
`TNCanvas` or `TNEditor` module, or to `TuberNotesApp/Workspace.swift`,
names in its commit message the one-line check a person must try on a
physical iPad. Pencil feel, stroke fidelity, and visual taste are Phillip's
verdict: record the evidence, leave the verdict.
